# 收录标准

我们的目标是找到能够学习和复用的图像工作方法。传播热度帮助发现线索，完整提示词、明确来源与实际输出决定能否进入精选。

## 三种记录状态

- curated：已打开原帖，作者归属清楚，有完整作者 Prompt、明确的 2.5 模型声明、可核对成图，以及保存完整 Prompt 的授权依据。仍需单独标记是否独立复现。
- candidate：有具体可回访的原帖或评论，但 Prompt、模型、成图、作者或授权证据尚未齐全。搜索索引和二手转引只能进入这里。
- reference：官方资料、版本说明、旧模型迁移参考。它们不计入 2.5 社区精选数。

本项目原创改写进入独立模板库，或将 prompt.kind 明确标成 adaptation。不能把推测、图片逆向描述、摘要当成作者原始 Prompt。

## 怎样判断值得收藏

1. 输出质量：构图、文字、材质、空间关系或编辑一致性有清楚的成功点。保存实际观察，避免只复述作者夸赞。
2. 指令完整：原文、参考图、前后轮编辑指令和必要参数可找到；缺少的条件逐一列出。
3. 可迁移性：更换产品、人物、场景或语言后仍有可利用的结构。
4. 新意：展示有区分度的视觉方向或方法；同类变体以代表案例优先。
5. 来源可信：优先原创帖与作者评论，关注模型标注、时间和生成证据。

每次进入精选，在 summary 写出收藏理由，在 outputEvidence 写出成图或前后对比的可核验位置，在 permissionEvidence 写出授权来源。热度不设跨平台统一分数，也不因为高票就跳过证据审核。

## 采集流程

先使用 data/watchlist.json 的查询，查看过去 24 小时，并补查过去 72 小时迟到的搜索索引。优先补齐已有候选，再添加少量有价值的新条目。

打开 X 原帖或作者回复，记录作者、发布日期、原文、模型、参考输入和成图。若无法访问，写明 full、search-index 或 secondary 的实际证据等级，并保存发现路径。

按 X 帖子 ID 去重。同一讨论串的不同作者案例可分别保留，但同一案例的转发与镜像不重复计数。普通页面保留有意义的查询参数。

热度只保存真实看见的数字及观测时间。X 点赞、回复和浏览量分开记录，不使用二手平台的互动数代替。未取得的数据填 null，不能用 0 或转帖热度代替。

发布时分开说明实际生成模型、作者声称模型与本项目独立复现状态。旧 Image 2 的强案例可以作为 reference，但不能改写成 2.5 成果。

## 原文与图片

来源公开不等于已经获得复制完整作品的授权。默认保存来源和原创摘要；短引用明确标为 excerpt，取得完整短指令时可以标为 original，但在授权和归属补全前仍保留候选。完整长 Prompt 须有授权或明确许可后再存储。

只有 permission-granted 或 licensed 的图片才可加入 media，并记录替代文本和授权依据。否则直接链接作者原帖。编辑封面必须标注不是生成结果。代码许可不覆盖第三方作品。

## 复现记录

本轮没有运行任何付费图像生成。后续如果进行测试，记录准确 model ID、日期、质量设置、输出尺寸、输入图片授权、完整指令、失败重试和结果路径。保留失败案例与局限，不能只凭作者成图把 reproduction 标为 passed。

## 每轮完成条件

更新来源数据与 docs/research 中的日志；日志记录实际检查时间、查询、候选增减、证据变化、访问问题与下一步。运行 npm run validate、npm test、npm run build。没有新发现也只在本地记下结果，避免反复通知相同信息。
